# Yulya Studio

A browser game studio prototype. Game projects are static browser assets and are never executed by the API. The frontend is React/TypeScript/Vite with Monaco; the API is FastAPI; MongoDB stores account and project metadata.

## First live deployment

- The first milestone is a public landing page and API health endpoint on Render.
- Google sign-in and Cloudflare are intentionally out of the first deployment.
- MongoDB Atlas is required for persistent account/project metadata. Set `MONGODB_URI` and `MONGODB_DATABASE` on the API service.
- On Render, set `APP_ORIGIN` and `API_ORIGIN` to the frontend and API URLs. Keep `SESSION_SECRET`, `API_KEY_ENCRYPTION_SECRET`, `API_KEY_HMAC_SECRET`, and `PREVIEW_TOKEN_SECRET` as separate high-entropy secrets.
- Email registration needs a verified Resend sender (`RESEND_API_KEY`, `EMAIL_FROM`). Until configured, visitors can browse but cannot register.
- Without R2, project files use local storage. Render's free service filesystem is ephemeral, so this is only suitable for the initial landing-page demonstration. Add durable object storage before using real projects.

## Local development

1. Use Node.js 20+ and Python 3.11+.
2. Copy `.env.example` to `.env`. The local API uses in-memory metadata and `.local-data/` file storage when MongoDB and R2 are not configured. Development-only cryptographic defaults are generated by the API; production refuses missing secrets.
3. Install frontend dependencies and run the API and Vite in separate terminals:

   ```powershell
   pnpm install
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   uvicorn backend.app:app --reload --port 8000
   pnpm dev
   ```

4. Open `http://localhost:5173`. Vite proxies `/api` to FastAPI. Configure Resend with a verified sender to receive email verification codes.

## Security model and later milestones

- Project file paths are validated as project-relative paths and object keys are namespaced by immutable owner/project IDs while private.
- Game code is served as static browser assets and is never executed by the API. The isolated preview uses a sandboxed iframe and restrictive content security policy; source-text filtering is not treated as a security boundary.
- The AI receives only project-scoped file tools. It has no shell, process, general filesystem, or network tools.
- Future milestones add durable object storage, isolated public game delivery, and the Gemini coding assistant. Keep provider keys on the API and never expose them to browser code.
